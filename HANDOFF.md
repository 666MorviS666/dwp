## Что это

Оценка вероятности победы в Dota 2: модель по драфту до старта и модель по
состоянию на поле поминутно. Применение — аналитика для знания исхода игры в 90% случаев

Упор сейчас на **лайв**, а не на офлайн-разбор. Это меняет выбор моделей и
приоритеты: важнее честность числа на экране и устойчивость, чем последние
тысячные log loss.

**Главное на экране — ВЕРДИКТ.** Требование было: «пусть посмотрит семь
минут и скажет, кто победит, и не колеблется ни разу, даже если
противоположная сторона имеет 90%». Сделано буквально: правило называет
сторону один раз и не меняет её никогда — **ветки смены в коде нет вовсе**.

```
сбылся                75.3%  [72.4, 78.0]  на 901 матче слепого холдаута
смен стороны за матч   0.00  против 1.87 у сырого процента
медиана минуты         11.0  вердикт появляется в 99.9% матчей
```

Ожидание уверенности окупается: назвать сторону ровно на 7-й минуте, не
глядя, — это 64.9%. Терпение стоит **+10.4 п.п.**

**Ручка, о которой надо знать сразу.** Порог уверенности 0.60 выбран под
бюджет «медиана не позже 10-й минуты». Он двигается, и двигается дорого:

```
порог  сбылось  вердиктов  медиана мин
 0.60   0.7533      0.999         11.0     ← сейчас
 0.70   0.8643      0.973         20.0
 0.80   0.9326      0.857         25.0
 0.90   0.9798      0.605         27.0
```

Хотите 86% вместо 75% и готовы ждать до 20-й минуты:
`python -m dwp.verdict --tune --budget 20 --min-commit-rate 0.95`.
Полная таблица — README, «Вердикт»; печатает `dwp.verdict --frontier`.

**Про «предсказание, а не аналитика вслед событиям».** Завести рядом
второй, «прогнозный» процент нельзя — калиброванная вероятность и есть
лучшая оценка исхода из доступной информации, и любое число поверх неё
будет либо той же величиной, либо хуже (замерено: продление темпа хуже
наивного, 0.1879 против 0.1796). Раньше вместо этого на панели стоял блок
«перспектива» — коридор, темп и что ещё не разыграно. **16.08.2026 он с
панели снят вместе с половиной остальных блоков:** на его вопрос отвечает
вердикт, одним словом вместо трёх таблиц. Сам замер жив и печатается —
`python -m dwp.forecast --check`.

## Как запустить

```powershell
python -m dwp                # интерактивное меню
python -m dwp.web            # веб-панель, http://127.0.0.1:8765/
```

**Панель — главный интерфейс, в ней три раздела:**

```
матчи                список идущих игр, клик по строке — панель матча:
                     ВЕРДИКТ, табло, сборки, карта, лента событий, драфт
данные и обучение    скачать матчи, обучить ансамбль, все замеры —
                     с живым логом и кнопкой «прервать»
точность             три главные строки, метрики моделей, калибровка лайва,
                     реестр вскрытий холдаута
```

**Раздел «точность» — три строки, ради которых его открывают.** Все три с
одного вскрытия слепого холдаута (1864 матча), поэтому их можно ставить
рядом:

```
лайв-модель, каждую минуту матча    72.7%   log loss 0.5180 · ECE 0.0121
драфт-модель, до начала игры        55.4%   AUC 0.5825
ВЕРДИКТ, одна сторона на матч       75.3%   [72.4, 78.0], на 11-й минуте
```

**Окна панели двигаются мышью** (16.08.2026): левый край — поменять с
другим окном местами, правый — ширина от 3 до 12 колонок, правый нижний
угол — масштаб от 60% до 200%. Кнопка «раскладка» показывает подсказку и
возвращает всё как было. Хранится в `localStorage`, ключ `dwp.layout.v1`.

Всё остальное (`dwp.live --watch --map`) — то же самое в консоли.

Переменные окружения: `STEAM_API_KEY` (лайв), `STRATZ_TOKEN` (пары героев).
**Токены только в окружении, в файлы проекта их писать нельзя.**
Оба на 16.08.2026 рабочие.

## Модели

```
models/ens_03..ens_13.pkl  21 признак  АНСАМБЛЬ, умолчание в бою.
                           Обучены 16.08.2026 на 12 500 матчах,
                           рейтинг ИГРОКОВ (--rating player)
models/live_exact.pkl      21 признак  одиночная, запасная
models/live.pkl            15 признаков базовая, умолчание test_live_replay
```

`models/attic/` больше нет: четырнадцать старых артефактов удалены
16.08.2026 (6.4 МБ). Все они были померены за один проход и все проиграли
боевому ансамблю; держать их дальше было незачем.

Умолчание такое: если в `models/` лежит `ens_*.pkl` хотя бы в двух
экземплярах — берётся ансамбль, иначе `live_exact.pkl`. Замер на всём
слепом холдауте: log loss 0.5233 против 0.5285 у средней одиночной
(интервал [−0.0057, −0.0047]) и **ECE 0.0082 против 0.0155–0.0315**. Второе
важнее: ECE — это насколько врёт число на экране.

Собрать набор заново:

```powershell
foreach ($s in 3,5,7,11,13) {
  python -m dwp.train --source real --live-features --extra-features `
    --exact-features --gold-norm add --rating player --seed $s `
    --out "models\ens_$('{0:d2}' -f $s).pkl"
}
python -m dwp.bench_models              # холдаут + кэш вероятностей
python -m dwp.verdict --tune --frontier # правило вердикта по этому кэшу
```

Порядок обязателен: `bench_models` пишет `data/holdout_preds.npz`, из
которого `verdict --tune` подбирает правило. Переобучили и не пересобрали —
вердикт остался от прежних моделей и об этом никто не скажет. То же одной
кнопкой: панель → «данные и обучение» → «Переобучить всё заново».

`--gold-norm add` обязателен: без него набор отличается от боевой модели на
два признака, и `load_models` его не примет. `--rating player` — умолчание,
но в команде оставлен явно: он меняет, какой рейтинг попадёт в
`draft_logit`, и артефакты двух пород лучше не смешивать в одном ансамбле.

## Проверки — прогонять после любой правки

```powershell
python -m dwp.test_live_replay --n 40 --model models\ens_*.pkl
python -m dwp.test_live_fixture
python -m dwp.test_collect_fake
python -m dwp.test_map_geometry
python -m dwp.test_builds
python -m dwp.test_killfeed
python -m dwp.test_forecast
python -m dwp.test_verdict
python -m dwp.test_web_snapshot
python -m dwp.livecheck --offline
python -m dwp.live --once --from-file data\live_dump_late.json --map
```

То же одной кнопкой: панель → «данные и обучение» → «Прогнать все проверки».

Все должны дать код 0. Главные два: `test_live_replay` сверяет лайв-путь с
офлайн-путём построчно, `test_web_snapshot` гоняет настоящий матч через тот
же `Poller.snapshot`, что работает в браузере, и сверяет число панели с
числом консоли до 1e-9. `test_builds` держит точность восстановления
инвентаря: если правка её ухудшит, он упадёт с числом. `test_verdict`
держит неподвижность вердикта (раздел 1 гоняет ряд, который переворачивает
сторону, и требует, чтобы вердикт не шелохнулся) и независимость
сглаживания от частоты опроса — панель опрашивает раз в 2 с, холдаут
поминутно, и разойтись они могут молча.

Раздел 8 в `test_web_snapshot` — про саму страницу: каждый id, к которому
лезет скрипт, есть в разметке; окна раскладки перечислены и в разметке, и в
скрипте; скрипт разбирается парсером JS. Это ловит класс поломок, который
питоновские стенды не видят в принципе: опечатка в id не роняет ничего,
просто половина экрана остаётся пустой. Нужен `pip install esprima`; без
него раздел честно скажет, что синтаксис не проверен.

## Слепой тест и холдаут

```powershell
python -m dwp.blindtest --seal --holdout --n 200   # исход при записи НЕ читается
python -m dwp.blindtest --reveal --holdout --worst 12
python -m dwp.holdout                              # сколько раз туда смотрели
python -m dwp.blindtest --quiz --n 10              # сыграть самому против модели
python -m dwp.blindtest --guesses                  # догадки из «слепого режима» панели
```

Два разных механизма, и путать их не надо. **Холдаут** — 15% матчей,
спрятанных от обучения навсегда (по хэшу `match_id`, а не по сиду, чтобы
добор данных не переносил матчи туда-сюда). **Слепой тест** — порядок
ходов: оценки записываются и закрываются контрольной суммой ДО того, как
кто-либо смотрит на исход; пересчитать `--reveal` можно сколько угодно, а
поправить модель и пересчитать по старому конверту — нет.

`train.py` исключает холдаут по умолчанию. Каждое вскрытие пишется в
`data/blind/registry.csv`: чем их больше, тем меньше в холдауте слепоты.

**Главное, что этот стенд уже показал:** разброс log loss от одного лишь
сида разбиения — **0.027**, вдвое больше вклада всего драфта. Ансамбль трёх
сидов даёт −0.0050 значимо. Подробности и таблицы в README.

## Упёрлись ли в потолок

**В потолок данных — да. В потолок задачи — нет.** Полный разбор в README,
раздел «Упёрлись ли в потолок обучения»; здесь итог.

Закрыто замером и переделывать не надо: больше матчей для стейт-модели
(дважды — кривой обучения и прямой проверкой 5253 → 12 500), эмбеддинги
героев, веса по свежести, сборки, урон, свободное золото, разнородный
ансамбль, одиночная модель вместо ансамбля. Сработало за всё время ровно
два раза: ансамбль и рейтинг игроков.

Где точность ещё лежит, по убыванию честной оценки:

1. **Первые пятнадцать минут** — там половина всей ошибки, и единственный
   сигнал там драфт с рейтингом. Драфт-модель линейная, пар не знает, 9 из
   10 коэффициентов на живом составе в пределах шума. Эмбеддинги на 7 тыс.
   матчей дали ноль — но выгрузка с тех пор выросла вдвое, и это первое,
   что надо перепроверить.
2. **`gold_adv`** — до 22 п.п. на экране в концовке, в 81% строк в пользу
   лидера. Это ошибка не в точности, а В САМОМ ЧИСЛЕ, которое видит
   зритель. Путь через журнал покупок закрыт, путь через модель буйбэков не
   пробован.
3. **Позиции игроков в рейтинге** — сейчас поправка Elo раздаётся пятерым
   поровну. Единственная неиспробованная деталь в том, что сработало.
   Нужны позиции в выгрузке, их нет.
4. **Тридцать матчей ОДНОЙ моделью** — не улучшение, а проверка честности
   на том, что реально показывали. До сих пор не сделано.

И отдельно, потому что это НЕ про точность модели, а про пользу: **порог
вердикта**. Поднять его с 0.60 до 0.70 — 86.4% сбывшихся вердиктов вместо
75.3%, модель при этом не меняется вовсе. Платится минутами.

## Открытые вопросы, по убыванию цены

1. **`gold_adv` — разные величины в обучении и в лайве.** Обучение берёт
   добытое золото, лайв подаёт нетворс. Причина расхождения найдена и
   измерена: буйбэки. Цена на реальном матче — до 22 п.п. на экране, в 81%
   строк в пользу лидера. **Это по-прежнему самая дорогая известная
   неточность**, и путь (а) теперь тоже закрыт замером (README,
   «Восстановление нетворса»). Что выяснилось попутно и чего раньше не
   знали: **зазор — явление поздней игры** (|медиана| 1871 золота посреди
   матча против 6487 в конце), а лайв-нетворс и офлайновый финальный
   нетворс расходятся даже в одной и той же точке — из 7 досмотренных
   записей сходится ОДНА. Пока это не объяснено, любая калибровка одной
   величины по другой строится на песке. Это и есть следующий шаг.

2. **Калибровка лайва: тридцати матчей ОДНОЙ моделью до сих пор нет.**
   Посчитанное значение — ECE 0.126 на восьми матчах против обещанных офлайн
   0.021–0.034. В логе 13 матчей с добранным исходом, но записаны они
   четырьмя разными моделями, и складывать их нельзя. Теперь умолчание —
   ансамбль, значит новые записи пойдут под одним именем; досматривать до
   конца. Это единственный замер, который меряет то, что видел зритель.

3. **Stratz: токен работает, сравнение вероятностей — нет.** Справочник пар
   на 127 героев добирается, строка «состав против состава» в блоке
   «почему» под драфтом считается на настоящих данных. А вот их
   live-вероятность не с чем сверять: живьём они ведут лиговые матчи, а
   записывали мы паблики. Она по-прежнему пишется в лайв-лог колонкой
   `p_stratz` (на экране её больше нет) — первый же турнирный матч под
   запись даст числа, считает `dwp.livecheck`.

4. **Драфт-модель слабая** — 127 коэффициентов, синергий не знает. На живом
   составе 9 из 10 коэффициентов в пределах шума; на слепом холдауте AUC
   0.5825. Рейтинг игроков её поднял (0.6001 → 0.6138 в шагающем протоколе),
   но упирается она в другое: пар у неё нет вовсе. Путь — эмбеддинги героев
   вместо одиночных коэффициентов; на 7 тыс. матчей это дало ноль,
   перепроверять на нынешних 12 500.

## Проверенное и отклонённое — не переделывать заново

- **Эмбеддинги героев в драфте** (синергия + контра, ранг 2/4/8, шагающий
  протокол): вклад НУЛЕВОЙ. Доказано контрольным прогоном — выключенные
  синергия и контра дают те же числа, что включённая контра.
- **Веса по свежести патчей**: четыре полураспада, все интервалы накрывают
  ноль. На выборке из двух патчей стареть нечему.
- **Восстановление командной разницы нетворса** (путь «а» в новой форме —
  не по игрокам, а сразу по разнице): в конце матча R² 0.71, посреди матча
  не держится. Коэффициент при буйбэке +2588 по концам против +7462 по
  живым логам — величины разной природы.
- **Больше матчей ради стейт-модели**: закрыто ДВАЖДЫ. Кривая обучения на
  полке с ~3200 матчей (последний шаг −0.0005 при ±0.0091), и прямая
  проверка — выгрузка выросла 5253 → 12 500, ансамбль переобучен с нуля,
  разница −0.0016 [−0.0038, +0.0006]. Оговорка: докачаны СТАРЫЕ матчи,
  патчей по-прежнему два, про свежесть замер ничего не говорит.
- **Свободное золото командой как признак**: пять сидов, значимо лучше у
  двух, знак скачет, средний эффект −0.0005 при разбросе по сидам 0.0079.
  Это была единственная величина из «чего модель не знает», которую вообще
  можно посчитать; остального в источнике нет.
- **Рейтинг игроков в стейт-модели**: для драфта значимо (AUC +0.0137), а
  до итогового числа не доходит (+0.0004, не значимо). Оставлен: лучше
  там, где решает, и не хуже нигде.
- **Одиночная модель вместо ансамбля**: ни одна из 11 меряемых не обошла
  боевой ансамбль ни по log loss, ни по Brier, ни по ECE.
- **Разнородный ансамбль** (5 сидов + 3 модели с другими гиперпараметрами):
  −0.0005, интервал [−0.0017, +0.0006] — не значимо, при +60% инференса.
- **Свой сид LightGBM у каждого участника ансамбля**: −0.0003, интервал
  [−0.0009, +0.0002]. Оставлено (правильнее по смыслу), но не улучшение.
- **«Если темп сохранится» как число на экране**: проекция производных на

  золоту сам возвращается к среднему, продление копит ошибку.
- **Динамический драфт** (вес состава растёт к поздней игре): сила драфта с
  длиной матча падает, а не растёт. Камбэки он не предсказывает.
- **Парные данные Stratz как признаки модели**: AUC одного признака 0.4964.
  Статистика пабликов не переносится на про-матчи.
- **Сдвиг `minute` на 90 с** предматчевой паузы: сдвига нет, вопрос закрыт
  замером. Добавка: на живом матче до горна `game_time` ОТРИЦАТЕЛЕН, то
  есть часы и правда идут от горна.
- **`graph_gold` вместо нетворса**: корреляция 0.44, величина другой природы.
- **Подгонка `gold_adv` множителем ×1.36**: чинит не то, ошибка не в масштабе.
- **Восстановление нетворса офлайн через журнал покупок** (путь «а» из п.0):

## Соглашения, которых стоит держаться

- **Молчаливого нуля быть не должно.** Не нашлось поле — `NaN` и запись в
  отчёт, а не ноль. Один раз это нарушили (здания), и оно перевернуло знак
  в эндшпиле — история в README.
- **Число без выборки не показывать.** Везде, где на экран идёт доля,
  рядом идёт её ошибка или размер выборки; незначимое помечается «≈» или
  блёклым, а не печатается как факт.
- **Допущение либо проверено данными, либо помечено как допущение.**
  Образцы: `config.XP_TO_LEVEL` (таблица выведена из данных, потому что
  справочная оказалась неверной), `config.MAP_IMAGE_SCALE` (подобран
  наложением и просмотром), `stratz.LIVE_SIDE_IS_RADIANT` (помечено и
  проверяется в livecheck).
- **Второй реализации инференса быть не должно.** `dwp.web` считает тем же
  путём, что консоль: `live.extract_state → build_row → predict`.
- **Отрицательные результаты записывать в README.** Они дороже
  положительных: экономят следующему заходу неделю.

## Технические грабли этой машины

- **PowerShell 5.1.** Нет `&&`, `??`, тернарника. `Select-Object -First N` в
  конвейере убивает upstream и даёт код возврата −1 — проверять коды
  отдельной командой.
- **Скрипты писать файлом**, не передавать here-string в `python -`:
  Windows Defender ловит шаблон `powershell -ExecutionPolicy Bypass
  -Command … | python -` эвристикой ClickFix и поднимает тревогу. Это
  ложное срабатывание, но пугает и мешает.
- **`> файл` в PowerShell пишет UTF-16.** Поэтому у `dwp.live --dump` есть
  `--out`, а чтение файлов определяет кодировку по BOM.
- **`Start-Process -Environment` в 5.1 нет** — переменные наследуются от
  текущего процесса.
