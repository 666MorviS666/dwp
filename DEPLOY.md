# Деплой для личного использования

Три вопроса подряд: что положить в git, как поднять панель одной командой и
почему на Vercel она не живёт.

---

## 1. GitHub

### Сначала поставить git

На этой машине его нет — ни в `PATH`, ни в обычных местах установки
(`Program Files\Git`, GitHub Desktop). Проверено. `winget` есть, поэтому:

```powershell
winget install --id Git.Git -e
winget install --id GitHub.cli -e     # необязательно, для `gh repo create`
```

После установки откройте терминал заново — `PATH` подхватывается только в
новых сессиях. Проверка: `git --version`.

### Дальше — репозиторий

Каталог ещё не под контролем версий. С нуля:

```bash
cd "C:\Users\cool9\OneDrive\Документы\prognoz"
git init -b main
git add .
git status            # ОБЯЗАТЕЛЬНО посмотрите список глазами
git commit -m "dwp: вероятность победы в Dota 2"
```

`git status` тут не ритуал. `.gitignore` держит вне репозитория 3.3 ГБ сырых
матчей и производные выгрузки; если в списке к добавлению мелькнёт
`data/matches/`, значит правило не сработало, и коммит на 3 ГБ придётся
вырезать из истории — а это заметно тяжелее, чем не делать его.

**Про OneDrive.** Проект лежит в `OneDrive\Документы`, и это стоит иметь в
виду: OneDrive синхронизирует и `.git/`, а он меняется пофайлово и часто.
Обычно работает, но конфликты синхронизации внутри `.git/` чинятся плохо.
Надёжнее держать рабочую копию вне OneDrive (например, `C:\dev\dwp`) — а
резервную копию обеспечит уже сам GitHub. Если переносить не хочется, хотя
бы исключите каталог проекта из синхронизации в настройках OneDrive.

Дальше — приватный репозиторий (панель личная, ключ Steam личный):

```bash
gh repo create dwp --private --source=. --push
# либо руками: создать репозиторий на github.com и
# git remote add origin git@github.com:<вы>/dwp.git && git push -u origin main
```

### Что едет и что нет

| едет | почему |
|---|---|
| `dwp/` | код и `README.md` — 218 КБ измерений, это главный документ проекта |
| `models/*.pkl` | 3.9 МБ. Без них свежий клон не запускается вообще |
| `data/*.json` | справочники героев и предметов, правило вердикта, таблицы горизонта и камбэков |
| `data/export_draft.csv.gz` | 426 КБ. Из него панель берёт «1210 м.» под каждым коэффициентом — без него значимость героев не считается и строки «почему» пропадают |
| `data/blind/` | запечатанный слепой тест. **Невосстановим по определению**: смысл печати в том, что её нельзя переиграть |
| `data/live_log/` | записи досмотренных матчей. Живой матч пересмотреть нельзя — это тоже невосстановимо, и на этом стоит страница «точность» |

| не едет | чем вернуть |
|---|---|
| `data/matches/` (3.3 ГБ) | `python -m dwp.collect --n 12500` — часы и лимиты OpenDota. **Держите отдельную копию**, git её не хранит |
| `data/export_frames.csv.gz`, `data/export_extras.csv.gz` | `python -m dwp.export` |
| `data/holdout_preds.npz` | `python -m dwp.bench_models` |
| `data/comeback_rows.csv` | `python -m dwp.builds --table` (~25 минут) |
| `data/stratz/`, `data/matchups/`, `data/assets/` | качаются сами при первом обращении |
| `__pycache__/`, `.env` | — |

### Лицензии в репозитории нет — и это выбор, а не забывчивость

Без файла лицензии по умолчанию действует «все права сохранены»: другие не
имеют права копировать и использовать код. Для личного приватного проекта
это ровно то, что нужно. Захотите открыть — положите `LICENSE` (MIT, если
хочется максимально просто) и допишите строку в `README.md`.

### Перед первым `push` — про ключи

Ключей в коде нет, проверено: `STEAM_API_KEY`, `STRATZ_TOKEN` и
`OPENDOTA_API_KEY` читаются только из окружения (`dwp/config.py`), в файлы
не пишутся и в лайв-логи не попадают. `.env` внесён в `.gitignore`. Правило
на будущее: **ключ, однажды попавший в историю git, остаётся в ней и после
удаления файла** — если это случилось, ключ надо не вычищать, а отзывать и
выпускать заново.

## 2. Docker — панель одной командой

```bash
cp .env.example .env          # вписать STEAM_API_KEY
docker compose up -d --build  # http://localhost:8765/
docker compose logs -f
docker compose down
```

Что заложено в конфигурацию и почему:

- **`libgomp1` ставится отдельной строкой.** lightgbm собран с OpenMP, и в
  `python:3.12-slim` этой библиотеки нет. Падает не обучение, а импорт — на
  загрузке `.so`, до первой строки логики.
- **Зависимости ставятся до копирования кода.** Правка `web.py` не должна
  тянуть пересборку колёс numpy и lightgbm: это минуты против секунд.
- **Порт открыт на `127.0.0.1:8765`, а не на `0.0.0.0`.** Панель не
  спрашивает пароля, и в ней есть кнопки «скачать матчи» и «переобучить всё
  заново». Выставить её в сеть — значит отдать эти кнопки и свой ключ Steam
  всем, кто найдёт адрес.
- **`data/` и `models/` подключены томами.** Лайв-логи и скачанные матчи
  должны переживать пересборку образа, иначе каждая правка кода стирает
  историю точности.
- **`DWP_HOME=/app`.** `dwp/config.py` считает корень как каталог на уровень
  выше пакета; переменная задаёт его явно и снимает зависимость от того, как
  проект разложен внутри образа.

Без Docker всё то же самое работает напрямую:

```bash
pip install -r dwp/requirements.txt
set STEAM_API_KEY=...          # Windows; в bash — export
python -m dwp.web              # http://127.0.0.1:8765/
```

## 3. Vercel: почему нет

Коротко: **не из-за размера и не из-за времени выполнения — из-за
состояния.** Ниже разбор с ссылками, потому что два расхожих возражения о
Vercel к этому проекту как раз НЕ относятся, и стоит знать, какие именно.

### Что НЕ мешает (вопреки ожиданиям)

| | ожидание | как на самом деле |
|---|---|---|
| размер сборки | «numpy + pandas + scipy + sklearn + lightgbm не влезут» | предел для Python — **500 МБ** несжатыми, а замеренный вес этих пяти пакетов — **244 МБ**. Влезает с запасом; для крупных сборок есть отдельный режим до 5 ГБ ([limits](https://vercel.com/docs/functions/limitations)) |
| время выполнения | «10 секунд на запрос» | на Hobby — **300 с** ([там же](https://vercel.com/docs/functions/limitations)) |
| «только Node» | «питон надо переписывать» | Python — штатная среда, есть даже деплой своего образа через `Dockerfile.vercel` ([containers](https://vercel.com/kb/guide/does-vercel-support-docker-deployments)) |

### Что мешает по-настоящему

**1. Функция не помнит ничего между вызовами.** Формулировка Vercel про
контейнерные функции — дословно: «Container-based functions are stateless.
Each instance takes a request, returns a response, and keeps nothing between
calls», и простаивающий экземпляр гасится через 5 минут. А панель держит
`Poller` — фоновый поток, который опрашивает Steam раз в несколько секунд и
**копит историю матча**. На этой истории стоит половина экрана:

- лента событий выводится из РАЗНИЦЫ между соседними опросами
  (`dwp/killfeed.py`) — журнала фрагов в `GetRealtimeStats` нет вовсе;
- коридор прогноза и реконструкция золота считаются по ряду минут;
- вердикт по построению не меняется после фиксации — а «не меняется»
  требует помнить, что он уже был выдан.

Без потока между запросами всё это придётся считать заново на каждый
запрос, из одной точки. Одной точки для разницы не хватает: лента станет
пустой, а вердикт — колеблющимся, то есть ровно тем, чего от него
добивались не допустить.

**2. Файловая система только на чтение.** Панель пишет: лайв-логи в
`data/live_log/`, матчи в `data/matches/`, модели в `models/`. Раздел «данные
и обучение» вообще запускает `python -m dwp.train` подпроцессом и стримит
его вывод. На serverless писать некуда, а подпроцесс на минуты — не та
задача, для которой существует функция.

**3. Панель не аутентифицирует никого.** Публичный адрес + кнопка
«переобучить всё заново» + ваш ключ Steam в переменных окружения. Это не
техническое ограничение платформы, но для «личного использования» —
решающий довод: личное должно оставаться личным.

### Что делать вместо

- **Локально или в Docker** — как в разделе 2. Для личного использования
  этого достаточно и это работает сегодня.
- **Нужен доступ снаружи** — тот же `Dockerfile` едет на любой хостинг с
  постоянно живущим процессом (Fly.io, Railway, Render, обычный VPS). Там
  фоновый поток жив, диск пишется, всё работает как локально. Обязательно
  закройте доступ: реверс-прокси с паролем или туннель, а не открытый порт.
- **Нужен именно Vercel** — туда имеет смысл выносить только ту часть,
  которая по природе одноразовая: калькулятор драфта (десять героев на
  входе, вероятность и разбор на выходе). Ему не нужны ни история, ни диск,
  ни lightgbm — только вектор коэффициентов из `models/*.pkl` и
  калибровочная кривая. Это отдельное маленькое приложение, а не перенос
  панели; скажите, если делать.
